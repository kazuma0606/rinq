## 発見した仕様上の注意点（バグではなく設計の明確化）

### 1. `Projected<U>` 状態に `enumerate` は使えない

`select` の後は `Projected<U>` 状態となり、それ以上の操作はできない（`collect` のみ）。
`enumerate` を使う場合は `select` の前に置く必要がある。

```rust
// NG: select 後に enumerate は不可
.select(|x| x * 2).enumerate()

// OK: enumerate → where_ → select の順
.enumerate().where_(|(i, _)| i % 2 == 0).select(|(_, x)| x * 2)
```

→ テストコードをこの順序に修正して全通過を確認。

### 2. `QueryBuilder::range` の戻り値は `Initial` 状態

`select` は `Filtered` 状態にのみ存在するため、`range` の直後に `select` は使えない。
`flat_map` を使って `Filtered` に遷移させることで解決できる。

```rust
// NG: Initial 状態に select は不可
QueryBuilder::range(1..=10i32).select(|x| x * x)

// OK: flat_map で Filtered に遷移
QueryBuilder::range(1..=10i32).flat_map(|x| std::iter::once(x * x))
```

### 3. `QueryBuilder::empty()` のターボフィッシュは不要

`empty::<T>()` の構文はコンパイルエラー。型は変数の型注釈または使用文脈から推論させる。

```rust
// NG: ターボフィッシュは不要
QueryBuilder::empty::<i32>()

// OK: 型注釈で明示
let b: QueryBuilder<i32, _> = QueryBuilder::empty();
```

### 4. `MetricsQueryBuilder::new` の引数順序

`new(inner, Arc<MetricsCollector>, operation_name: String)` の順序。`collector` は `Arc` でラップする。
